# 【项目提示词】

```
你正在为一个 **ROS2 + C++17 模块化灵巧手控制系统**（仓库 Inspire_Hand_SDK）添加
新的**单自由度电动夹爪**支持。请严格按以下架构与约定完成。

═══════════════════════════════════════════════════════════════
1. 项目背景（先了解）
═══════════════════════════════════════════════════════════════
工作区是 colcon 单层 src/ 布局，根目录 = colcon workspace 根。
三个核心包：

  src/inspire_serial_core/   纯 CMake 裸库：Protocol 抽象、串口、配置加载、
                             日志、协议工厂自注册（SHARED .so）。
  src/driver/                ROS2 功能包 inspire_control_ros2：
                             节点 inspire_control_node、RegisterController、
                             各机型 InterfaceAdapter、InspireControllerFactory。
  src/interfaces/<机型>/     ROS2 接口包（msg/srv 单独成包）。

通信模式（所有机型统一）：
  ① 话题：50Hz 定时读寄存器并发布状态；订阅命令话题写。
  ② 服务：按需调用的 set/get（每寄存器一个 .srv）。
  ③ 组合服务（力控/触控）：内部 ioWriteSequence 在 DeviceWorker 单线程
     上原子串行写多寄存器，步骤间隔 3ms 由 worker 线程 sleep，
     回调不阻塞，天然不与定时读交错。

线程模型：
  主线程 MultiThreadedExecutor；
  每设备一个 DeviceWorker（请求队列 + 单工作线程）→ 串口事务永不交错；
  每设备一个 Boost.Asio 异步接收线程；
  定时器回调与服务/订阅回调分到不同 CallbackGroup，并发进入但 worker 串行化。

═══════════════════════════════════════════════════════════════
2. 添加新夹爪/机型的强制步骤
═══════════════════════════════════════════════════════════════
A. 协议层 src/inspire_serial_core/
   ① 新增 include/<Model>_protocol.hpp + src/<Model>_protocol.cpp，
      继承 Protocol 抽象类，实现 9 个虚函数：
        getRegisterAddress / buildReadCommand / buildWriteCommand /
        parseResponse / validateChecksum / parseTouchData /
        writeRegister / readRegister / readTouchData
   ② 文件末尾 REGISTER_PROTOCOL("<Model>_<bus>", <Model>_<bus>_Protocol);
      自注册到 ProtocolFactory。
   ③ src/inspire_serial_core/CMakeLists.txt 的 add_library(...) 列表追加 .cpp。
   ④ src/config_loader.cpp::interfacesProfileFromProtocolType() 末尾追加
        if (protocol_type.rfind("<Model>", 0) == 0) return "<Model>";
      （首段前缀匹配，protocol.type 可写 Model_485 / Model_canfd / Model_serial_can）
   ⑤ src/inspire_serial_core/tests/ 追加 test_<model>_<bus>_protocol.cpp
      覆盖：寄存器地址映射、读/写命令字节序列（含完整帧比对）、
      校验和（合法/篡改/长度非法/帧头错）、应答解析（同/异 hand_id、异 op_type）、
      A5 转义还原（若有）、parseResponse/parseTouchData 边界。
      加入 tests/CMakeLists.txt 的 add_executable(... ) 列表。

B. ROS 接口包 src/interfaces/<Model>/
   ① package.xml：<name> 用全小写下划线 ros 包名；
      <description> 注明通信方式 + 机型。
   ② CMakeLists.txt：rosidl_generate_interfaces 列出所有 msg/srv。
   ③ msg/GripperState.msg（与文档状态寄存器对齐）+ msg/SetInt32.msg。
   ④ srv/TriggerForHand.srv（hand_id → bool+message）、
      srv/SetInt32Value.srv（hand_id+value → bool+message）、
      srv/GetScalarForHand.srv（query+hand_id → value+message）。
   ⑤ 如有力控/触控组合，按需 srv/ForceModeGrasp.srv、ForceModeOpen.srv、
      TouchModeGrasp.srv、TouchModeOpen.srv（均 hand_id+speed+force）。

C. ROS 适配器 src/driver/
   ① include/<Model>_interface_adapter.hpp 继承 InterfaceAdapter，
      实现 wireTopics / wireServices / publishRegisterData / publishTouchData。
   ② src/<Model>_interface_adapter.cpp：
      - wireTopics：按 topic_config.name 分发
        （gripper_state 走 publishRegisterData；
         open_len_set / speed_set / force_set / catch_mode_set 等用 SetInt32 订阅）。
      - wireServices：写寄存器按 is_trigger_register 分流
        （TriggerForHand vs SetInt32Value）；
        读寄存器用 GetScalarForHand（白名单校验，未映射则 throw）。
      - 组合服务：读 ROS 参数 <model>_composite_service_prefix
        （默认 "/gripper"），注册 force_mode_grasp / force_mode_open /
        touch_mode_grasp / touch_mode_open。
        步骤顺序：catchMode → speedSet → forceSet（按厂商手册），间隔 3ms。
   ③ src/driver/src/interface_adapter_factory.cpp::makeInterfaceAdapter 追加
        if (interfaces_profile == "<Model>")
            return std::make_unique<<Model>InterfaceAdapter>(...);
   ④ src/driver/CMakeLists.txt：
      - find_package(<model>_interfaces REQUIRED)
      - add_executable(...) 列表追加 .cpp
      - ament_target_dependencies(...) 列表追加 <model>_interfaces

D. 配置示例 src/driver/config/
   ① device_protocol_<model>_example.yaml：
      protocol.type: <Model>_<bus>，devices 含 port/baudrate/Hand_ID。
   ② ros2_controller_<model>_example.yaml：
      device_nodes 含 topics 与 services；
      topic.name 必须是适配器约定的已知名
      （gripper_state / open_len_set / speed_set / ...）；
      services 写寄存器配 is_write_register: true，读寄存器配 get_service_name。

═══════════════════════════════════════════════════════════════
3. 关键命名与约束
═══════════════════════════════════════════════════════════════
- protocol.type 形如 "<MODEL>_<bus>"（大写下划线）。
- interfaces_profile 是去掉 _<bus> 后缀的型号（如 RH56DFX_serial_can → RH56DFX）。
- 寄存器名称用驼峰：openLenSet / speedSet / forceSet / gripperStatusBlock ...
  与厂商手册一致；首次出现的寄存器必须同时登记 REGISTER_MAP 与
  REGISTER_READ_LENGTH_MAP（除非只写不读）。
- 写组合服务步骤间隔用 constexpr int kCompositeStepMs = 3。
- 写帧帧头/帧尾/A5 转义按厂商手册；写帧 Meta 字段以**厂商跑通的 demo/SDK 为准**
  （手册与 demo 不一致时优先 demo，详见 §6）。
- 校验和：
    485 协议按 sum(byte[2..n-2]) & 0xFF；
    Serial-CAN 协议按 sum(ExtId..Meta) & 0xFF。
- 每条 service 回调必须用 rosIncomingHandIdTargetsThisNode 校验 hand_id
  （hand_id==0 视为兼容旧客户端仍受理）。
- 配置文件示例必须 install 到 share/inspire_control_ros2/config/
  （已在 CMakeLists.txt install(DIRECTORY config/ ...) 配置）。

═══════════════════════════════════════════════════════════════
4. 完成后的自检清单（按顺序执行）
═══════════════════════════════════════════════════════════════
[ ] colcon build --packages-select <model>_interfaces inspire_serial_core \
                                              inspire_control_ros2
[ ] colcon test --packages-select inspire_serial_core（新协议测试必须通过）
[ ] 启动示例配置，ros2 node list 应见 <device>_node
[ ] ros2 service list | grep <model>_interfaces （组合服务已注册）
[ ] ros2 topic list | grep /gripper/ （状态/命令话题已发布）
[ ] 真机联调：力控组合服务、状态话题定时器、定时读与组合写不交错。
[ ] README.md 更新：
    "ROS2 接口说明" 表追加新机型一行；
    项目结构图追加 interfaces 子目录；
    新增 "<机型> 夹爪全链路说明" 章节
    （含协议要点、寄存器表、配置示例、收发自检命令）。

═══════════════════════════════════════════════════════════════
5. 当前已支持的机型（避免重复实现）
═══════════════════════════════════════════════════════════════
- RH56F1_485（6 自由度灵巧手，电容触觉 version1）
- RH56H1_485 / RH56H1_canfd（6 自由度灵巧手，压阻触觉 version2）
- RH56DFX_serial_can（Serial-CAN 灵巧手）
- RH5DG2_485 / RH5DG2_canfd（13 自由度灵巧手）
- EG5CD1_485（单自由度夹爪 RS485，含力控/触控组合）
- EG2_4C2_serial_can（单自由度夹爪 USB-CAN 串口，仅力控组合）
- RH524J1_485（065 腱绳驱动 24 自由度灵巧手，寄存器见 065demo/hand_param.h）

═══════════════════════════════════════════════════════════════
6. EG2-4C2 适配的关键技术细节（最容易踩坑）
═══════════════════════════════════════════════════════════════
1) ExtId 编码用手册第 4 章位域：op_type<<26 | addr<<14 | hid，
   **不是** demo_can.py 的 "0000000 + bin(address)" 字符串拼接算法。
2) USB-CAN 串口模块的 reg_addr 填 **Modbus 地址**（1010/1060 等），
   不是原生 socketcan 用的 +10/+60 偏移地址（1020/1120）。
3) 写帧 Meta[0] 填实际有效数据长度（CAN DLC），不包含 Data[8] 末尾
   的 0xFF 填充：写 1/2/3/4 个 int16 寄存器分别填 2/4/6/8。
   单寄存器 Topic 写入若错误地固定填 8，会把填充字节当作后续寄存器
   数据，表现为串口有回包但夹爪不运动。
4) 读帧 Meta[0] 固定填 0x01（demo READ_META）。
5) 校验和从 byte[2]（ExtId 第 1 字节）开始到 Meta 末尾累加 & 0xFF。
6) 应答帧数据区固定偏移 frame[6..14]，0xA5 转义规则同 RH56DFX_serial_can。
7) 4C2 手册只定义 catchMode 0/1（位置/力控），无触控模式：
   - 不实现 TouchModeGrasp/Open；
   - 不实现 catchModeClose/catchModeOpen 寄存器。
8) gripperStatusBlock = 1060 起读 12 字节（6 个 int16），跨单帧 8B 上限，
   协议层自动拆 8+4 两帧（与 RH56DFX_serial_can 4+2 分包策略对齐）。

═══════════════════════════════════════════════════════════════
7. RH524J1（065 腱绳手）适配的关键技术细节
═══════════════════════════════════════════════════════════════
1) 帧格式复用 RH5DG2_485（EB 90 / 90 EB），不要复用 EG2_4C2。
2) 寄存器地址用 065demo/hand_param.h 的 100/200 分区，禁止套用
   RH5DG2 的 1000+ REGISTER_MAP。angleSet=320，angleAct=416。
3) HAND_NUM_DRV=24，angleSet/forceSet/speedSet/angleAct 等为
   24×int16，默认读写 48 字节；065 手支持单帧写满 24 路。
4) 角度限位与 demo_485_cable_driven_hand.py 一致：
   ID2~5 -200~200；ID18/19/23/24 0~1000；ID1 小指翻折 -150~0；其余弯曲 0~900。
   ROS joint_values 按下标 = 电缸 ID−1 排列（与实机一致）。
   实机拇指指尖/掌指（用户下标 19/21，对应 ID20/ID22）在协议层对调。angleSet 支持 -1 占位保持当前值。
5) 无触觉、无力控组合服务、无 actionSeq/actionLibrary、无百分比接口。
   ROS 话题：angle/force/speed/current；读服务含 temp、errorCode、status、
   currentAct、forceAct、angleAct。yaml 缺项时工厂按机型补齐，不改适配器接线。
6) 参考实现模板：RH5DG2 全套文件（协议/接口包/适配器/配置）。
7) demo 源：065demo/hand_param.h + demo_485_cable_driven_hand.py。
8) device_protocol 的 devices[].name 必须等于 launch 的 --device。
```

# 典型任务用法

把上面【项目提示词】整段贴进 AI 上下文后，**额外加一句任务**即可立即开工：

- "**按此项目提示词，为新机型 XXX 夹爪完成全链路适配**"
- "**按此项目提示词，把 gripper_demo_yyy.py 适配进项目**"
- "**按此项目提示词，复用 EG2_4C2_serial_can_Protocol 的实现给 XXX 夹爪改地址表**"
- "**按此项目提示词，把 XXX 文档里的寄存器表换成 EG2-4C2 的地址（1010/1060 等 Modbus 地址）**"
- "**按此项目提示词，把 065demo 的 RH524J1 腱绳手适配进项目（24DOF / RH5DG2 架构）**"

AI 会自动按 [1]→[6] 的顺序、命名约束、自检清单执行，**无需你重复解释项目架构**。
